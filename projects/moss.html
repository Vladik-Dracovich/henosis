TECHNICAL OVERVIEW / FIVE NOTES

MOSS is an independently developed window manager written in Common Lisp. Its central design concern is the relationship between window placement, user-defined policy, and a continuously available Lisp runtime. Rather than treating configuration as a static file consumed only at startup, the project approaches the desktop as a programmable system whose behavior can be examined and revised while it is running.

The proposed architecture separates window-management policy from the mechanisms used to communicate with a display environment. This distinction matters because focus handling, geometry, workspace state, and layout selection are separate concerns from the protocols that deliver window events. The goal is to keep those boundaries explicit without claiming support for any particular display server before that support exists.

Dynamic tiling is an important part of the design. Layout decisions should be expressible as functions over window and workspace state, with predictable operations for focus movement, rearrangement, resizing, and the creation of new layouts. A programmable command layer would allow those operations to be composed rather than hard-coded into a fixed set of shortcuts.

Common Lisp makes interactive development especially relevant: functions can be redefined, internal state inspected, and experiments evaluated without a full edit–compile–restart cycle. MOSS aims to take advantage of those facilities while still requiring careful treatment of errors, state consistency, event dispatch, and recovery when a user-defined function fails.

MOSS is a local, privately developed project and is not being presented as a released window manager. Implementation details and supported environments will be documented as they are validated. The intention is to complete and test the core behavior before publishing a usable release; the project is not currently advertised as available through the public GitHub archive.
